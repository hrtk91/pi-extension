# バックグラウンド圧縮

Pi の標準圧縮をフォールバックとして残しつつ、古い会話を非同期で要約する拡張機能です。要約中も通常の会話を続けられます。

- `src/`：Pi の拡張機能ディレクトリにインストールされる実行ファイル
- `test/`：ユニットテスト、プロンプト一致確認、インストール・読み込みテスト
- `validation/`：効果測定の概要、集計結果、テスト結果

## インストール

このディレクトリで実行します。

```sh
./install.sh
```

実行ファイルを `${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}/extensions/background-compaction` にコピーし、エージェント用ディレクトリの `settings.json` を更新します。変更前のファイルは `backups/background-compaction/` に保存されます。

`PI_CODING_AGENT_DIR` を設定すると、インストール先を変更できます。既定値は `~/.pi/agent` です。

アンインストールする場合も、インストール済みファイルはバックアップに残ります。

```sh
./install.sh --uninstall
```

## 動作

- モデルは固定していません。保存済みの既定モデルがあればそれを使い、なければ Pi で選択中のモデルを使います。モデルやプロバイダーの設定、利用可能な出力長などにより、要約できない場合があります。
- モデルの既定値は `/bgcompact model set provider/model-id` で設定できます。設定は `${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}/extensions/background-compaction.json` に保存され、再起動せず次の要約から反映されます。チャットで使用中のモデルは切り替わりません。この設定ファイルは拡張機能の更新・アンインストール後も残ります。削除するには `/bgcompact model reset` を実行してください。
- コンテキストウィンドウの使用量が 50% に達すると、自動で要約を開始します。
- ユーザーの直近 20% のターンを残し、1 回につき最大 80 ターンを要約します。
- 要約には Pi 標準のシステムプロンプト、要約用テンプレート、シリアライザー、ファイル一覧の形式を使います。
- 出力上限は Pi の既定の予約トークン数（16,384）の 80% です。要約は 30 秒でタイムアウトします。
- Pi 標準の圧縮が始まった場合、進行中のバックグラウンド要約を中止し、標準の圧縮に切り替えます。

TUI では要約中の対象ターンと経過時間をフッターの状態表示に設定し、完了または中止すると消します。TUI 以外で自動要約を開始した場合は開始通知を表示します。

`/bgcompact` を使うと、自動開始の 50% しきい値を待たずに要約を始められます。Pi がアイドル状態で、直近のアシスタント応答がある場合に実行できます。セッション再開直後にも使えます。要約は安全に適用できる次のターン境界で会話に反映し、手動実行では開始時と準備完了時に通知します。

- `/bgcompact`：保存済みの既定モデル（なければ Pi で選択中のモデル）で実行
- `/bgcompact provider/model-id`：その1回だけ指定モデルで実行
- `/bgcompact model`：現在のモデル設定を表示
- `/bgcompact model set provider/model-id`：自動・手動要約で使う既定モデルを保存
- `/bgcompact model reset`：保存した既定モデルを解除し、Pi で選択中のモデルに戻す

指定モデルが利用できない、または認証されていない場合は通知して中断し、別モデルへ黙って切り替えることはありません。

診断コマンド（`/bgcompact-status`、`/bgcompact-probe`、`/bgcompact-selftest`）は、Pi の起動時に `PI_BGCOMPACT_DEBUG=1` を設定した場合だけ使えます。

```sh
PI_BGCOMPACT_DEBUG=1 pi
```

診断用のプロバイダー接続テストは、保存済みの既定モデル（なければ Pi で選択中のモデル）を使います。

## テストと検証

リポジトリのルートで実行します。

```sh
npm test
```

Pi 標準のプロンプトとの一致、自動・手動の開始条件、要約範囲、キャンセルとフォールバック、モデルの選択・既定値の保存と解除・1回限りの上書き、診断コマンドの表示制御、インストール・読み込み・アンインストールをテストします。スモークテストからモデルへのリクエストは送信しません。

効果測定は `gpt-6-luna` で行った探索的なもので、他のモデルでの性能や一般的な優位性を示すものではありません。集計結果と生成アプリのテスト結果は [`validation/`](validation/) にあります。実行ごとの内部状態、通知ログ、一時ディレクトリのパスはリポジトリに含めていません。
